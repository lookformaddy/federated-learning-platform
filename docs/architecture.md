# Federated Learning Platform — Architecture

## Components

| Component | File | Responsibility |
|---|---|---|
| Config | `flp/config.py` | All run knobs, validated on construction |
| Synthetic data | `flp/synthetic.py` | Deterministic global data + non-IID client partitions |
| Model | `flp/model.py` | From-scratch logistic regression, deltas, clipping |
| Client | `flp/client.py` | Local trainer, FedProx term, latency/dropout simulation |
| Aggregation | `flp/aggregation.py` | FedAvg, trimmed mean; strategy dispatch |
| Privacy | `flp/privacy.py` | Clipping, Gaussian noise, epsilon accountant |
| Secure agg | `flp/secure_agg.py` | Zero-sum masks, masked exchange, server view |
| Metrics | `flp/metrics.py` | Global eval, per-client fairness, comm accounting |
| Registry | `flp/registry.py` | Versioned models, promotion gates, rollback |
| Orchestrator | `flp/orchestrator.py` | Round loop: sample → train → mask → aggregate → DP → eval → register |
| API | `flp/api.py` | FastAPI service (guarded import) |
| CLI | `flp/cli.py` | `train` / `demo` commands |

## Round lifecycle

1. **Budget gate.** If the next round would exceed the DP epsilon
   budget, training halts before spending privacy it does not have.
2. **Sampling.** `participants_per_round` clients are sampled with
   straggler-aware weights (inverse to observed latency).
3. **Local training.** Each sampled client trains from the global model
   for `local_epochs` full-batch steps. FedProx adds a proximal term
   `mu * (w_local - w_global)` to keep skewed clients near the global
   model. Deltas are clipped to `dp_clip_norm`.
4. **Deadline.** Simulated latency is drawn per client; a configured
   straggler (or an unlucky draw) exceeding `round_deadline_ms` is
   dropped for the round. Fewer than `min_participants` completions
   halts the run honestly.
5. **Secure aggregation.** Zero-sum masks are generated over the
   completed set; each client sends `delta + mask`. The server sums the
   masked deltas — masks cancel exactly — and never holds an individual
   update. The orchestrator asserts masked-sum == true-sum each round.
6. **Aggregation + DP.** The chosen strategy (FedAvg size-weighted,
   or trimmed mean) produces the global delta; Gaussian noise is added
   to the aggregate and the round's epsilon is charged.
7. **Evaluation.** Global loss/accuracy on the held-out set, per-client
   accuracy (fairness spread), and bytes up/down are recorded.
8. **Registry.** The new global model is versioned; it promotes only
   if accuracy beats the previous best *and* the DP budget is intact.

## Threat model (what is and is not protected)

- **Protected (simulated):** the server cannot see individual updates
  (masking); individual updates cannot dominate the aggregate (clipping
  + optional trimmed mean); privacy spend is bounded and fail-closed
  (accountant).
- **Not protected:** this is a simulation — masks are generated by the
  coordinator, not from pairwise client secrets, so a malicious
  coordinator could in principle reconstruct updates. Real deployments
  need pairwise Diffie-Hellman masking + Shamir secret sharing, plus
  dropout recovery that does not leak masks. The DP accountant uses
  linear composition (conservative, no amplification); use RDP in
  production.

## Failure model

| Failure | Behaviour |
|---|---|
| Straggler exceeds deadline | Dropped for the round; training continues |
| Too few participants after drops | Run halts with a clear reason |
| DP budget exhausted | Training halts before the next round |
| Corrupted / poisoned update | Trimmed mean bounds its influence |
| New global model is worse | Recorded but not promoted; rollback available |
| All clients drop in a round | Halt (min-participants gate) |

## Data flow

```
synthetic partitions (per-client, private, never leaves the client)
        │
        ▼ local training → clipped delta → + zero-sum mask
        ▼ masked delta (server view: aggregate only)
        ▼ strategy aggregation → + Gaussian noise (DP)
        ▼ global model update → eval → registry (gated promotion)
```

## Determinism

All randomness flows from `FLConfig.seed`: data generation, partition
skews, sampling, latency jitter, masks, and DP noise. Same seed →
identical loss/accuracy trajectory (verified in `test_orchestrator.py`).
